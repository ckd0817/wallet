# 无障碍自动恢复

普通应用没有重新绑定无障碍服务的公开接口。本项目内部 Debug 版通过本机 ADB 一次授予 `WRITE_SECURE_SETTINGS`，仅在用户已经开启记账无障碍、但系统实际绑定列表中没有该服务时，短暂移除并重新加入自身组件。

## 应用内授权引导

从 `2.3.5-debug`（12）起，统一进入“设置 → 记账 → 使用设置”，可查看通知权限、本机恢复授权、无障碍实际连接和电池优化状态，配置识别模型，复制授权命令、打开开发者设置及后台自启动设置。点击“授权步骤”查看电脑授权步骤与常见错误处理。

授权检测直接查询本机系统，不保存到账本或云端；从系统设置返回时自动刷新，“使用设置”展开期间每 5 秒检测一次。命令复制通过 Android 原生剪贴板完成，复制成功与授权成功分别显示。

后台自启动缺少跨厂商的可靠公开检测接口，界面提示在系统设置确认，不把“打开过设置”视为已授权。优先打开厂商自启动页面，打不开时回到本应用的信息页面。其他用户仍需在自己的手机上完成一次 ADB 授权，云端更新不会自动授予该权限。

安装后执行一次：

```powershell
& 'E:\AndroidStudioSDK\platform-tools\adb.exe' shell pm grant com.smartwallet.app android.permission.WRITE_SECURE_SETTINGS
```

覆盖安装及普通重启通常保留授权，卸载重装或系统撤销授权后需要重新执行。本权限允许修改系统安全设置，代码只用于恢复本应用的无障碍连接。

小米手机还需允许“后台自启动”。本次真机 `OS3.0.309.0.WOKCNXM` 的系统日志曾明确拒绝启动恢复任务，应用操作 `MIUIOP(10008)` 为 `ignore`；设为 `allow` 后后台进程可重新启动。本机已执行：

```powershell
& 'E:\AndroidStudioSDK\platform-tools\adb.exe' shell cmd appops set com.smartwallet.app 10008 allow
```

`10008` 是该小米系统的厂商操作编号，不应直接用于其他厂商设备；其他设备通过系统设置允许自启动。

## 检测与恢复

- 进程启动 15 秒后开始检查，进程存活期间每轮检查完成后间隔 20 秒。
- WorkManager 每 15 分钟安排一次后台兜底，不依赖网络；调度会受休眠、省电与厂商后台限制影响，不保证准时执行。
- 重连前再次等待并检查 3 秒，给系统正常连接留出时间。重连后读取实际绑定结果，失败后继续重试，同一进程至少间隔 60 秒。
- 用户主动关闭无障碍时跳过恢复，不根据历史授权强行开启。
- 重连只改记账组件，重新加入前读取最新服务列表，保留其他服务的变化。
- 重连开始前同步保存待完成标记；如果进程在临时移除组件期间退出，下次检查先补完操作。
- 未获得一次授权时不操作系统设置。强行停止应用后，Android 会停止后台任务，需再次打开应用才能继续检测。

## 排查

```powershell
& 'E:\AndroidStudioSDK\platform-tools\adb.exe' logcat -d -s WalletA11yRecovery SmartWalletCapture
& 'E:\AndroidStudioSDK\platform-tools\adb.exe' shell dumpsys accessibility
```

`Service reconnected` 表示重连后的系统绑定检查通过；不能仅凭开关为开启判断服务健康。

2026-10-28 真机现场曾出现 WebView 更新终止共享主进程、无障碍仍启用但被列入异常列表。本机制恢复这类残留断连；系统原始断开日志未完整保留，不能将所有历史故障归因于 WebView。
